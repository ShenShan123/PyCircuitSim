## Key definitions (read this first)

- **`.op` vs `.tran`.** `.op` finds one DC operating point (~41 NR iterations
  for these arrays). `.tran` steps through time; each accepted timestep runs
  its own NR solve. The workload that matters is the **write op**: wordline
  pulse + bitline drive, 10 ns at 50 ps steps = **200 accepted timesteps ≈
  483 NR iterations + ~620 factorisations + 200 commit points**. Revisions
  1–3 budgeted on `.op`; rev 4 re-ranked everything on the transient.
- **NR iteration.** One Newton-Raphson pass: evaluate every device at the
  current voltage guess (NN forward + autograd Jacobian), *stamp* the results
  into the MNA matrix, solve the linear system, update voltages. Every
  per-iteration cost is multiplied by 483 per write op — and by ~24,000 for a
  10⁴-step characterisation run.
- **MNA / stamping / transcap stamp.** Modified Nodal Analysis: the sparse
  conductance matrix + RHS the solver assembles each iteration. "Stamping" is
  the per-device Python loop writing each device's conductances into it. In
  transient, the charge/capacitance companion model adds a second stamp
  (`_stamp_mosfet_transient`, the **transcap stamp**) that roughly **doubles**
  the stamping cost vs DC. [M]
- **Factorisation vs solve; ordering; fill-in.** Solving `Ax=b` sparsely =
  factorise A into LU (expensive), then triangular solve (cheap: 30–600×
  cheaper). Today `spsolve` re-factorises from scratch every call — ~620×
  per write op. Factorisation cost is governed by **fill-in** (new nonzeros in
  L/U), which depends on the column **ordering**. scipy's default `COLAMD`
  blows up on these structurally-symmetric matrices (up to 399× fill);
  `MMD_AT_PLUS_A` holds fill flat at **1.6×** and is **76× faster at 128×64**,
  invariant to node ordering. [M, §5.2]
- **The commit path (rev 4's discovery).** After each *accepted* timestep the
  solver commits charge history per device: `get_charges(timestep_voltages)`
  at `solver.py:2238` + `update_charge_state()`. The solved voltages were
  never evaluated by the NR-loop batch eval, so the warm cache never matches:
  **every device runs a cache-cold, batch-1 forward + 3 backwards, every
  accepted step**. Call-count arithmetic is exact (200×96+96 = 19,296 at
  4×4). Measured **75–85 % of transient wall at 4×4/8×8/16×16**. [M, §2.4t]
- **Batch eval / warm cache.** `_batch_eval_nn_mosfets` groups devices by
  shared `nn.Module` (an SRAM array = exactly 2 groups, NMOS + PMOS, any
  size) and evaluates each group as one batched tensor call, caching per-device
  results so the subsequent per-device `get_conductance`/`get_charges` calls
  are free. Batch-1 eval is weight-streaming-bound (V7.0.0): per-call cost
  ~3.65 ms that does **not** fall with N — which is why the commit path is a
  pure scaling pathology, invisible at ≤20-device gate size.
- **LM ladder.** When an NN circuit's residual grows, `_solve_mna` retries
  with Levenberg-Marquardt damping — extra factorisations without extra NN
  evals. It **fires in transient**: 620 solves vs 483 batch evals (+28 %),
  identical at all measured sizes. Solver estimates must use the solve count.
  [M]
- **Bit-identical vs perturbing.** *Bit-identical* = byte-identical outputs,
  ships default-on, no re-gate. *Perturbing* = same math, different float32
  summation order (batched GEMM rows ≠ single-row eval; `F.linear` is not
  row-stable — V7.0.0), so results can land a different NR basin in a bistable
  latch. Perturbing work ships **default-off behind env flags** and gates
  together under §8.4. The commit-batch fix is perturbing *and* feeds the
  committed charge history into every later step — hence flag + gate despite
  being ~10 lines.
- **Movement-inclusive (M-rules, §1).** Every GPU number brackets build-input
  → H2D → forward+autograd → D2H → host consumption, with
  `torch.cuda.synchronize()` at both ends; median-of-≥30 on an idle GPU;
  CPU baseline is the 1-thread gate config. Headline metric = end-to-end wall
  clock including parse.
- **Parse.** Netlist → Circuit. Today `O(devices × checkpoint)`: one
  `torch.load` **per device** (55 % of parse), per-device `NormStats`/sidecar
  loads, per-device stdout. On `.op` parse is 83–85 % of post-fix runtime; on
  the transient it amortises to 1–8 % today, ~30 % at end-state. [M, §6]
- **Track A / Track B.** A = one large array, one MNA system (read/write
  transients, 32×16 … 256×128 = 3,072 … 196,608 devices). B = **≥100
  transient Monte Carlo re-runs of a full array** with per-device mismatch;
  deliverable is a distribution tail, not a mean.

## The measured picture

1. **The commit path dominates the transient: 75–85 % of wall** at every
   measured size. At 32×32 it alone is **13–22 s per timestep**; at 256×128,
   ~7–12 min per step → **~24–40 h per 200-step write op**. Nothing else in
   the plan touches a term this size. [M, §2.4t]
2. **NR/step = 2.42**, size-independent (4×4/8×8/16×16); no dt-halving;
   LM ladder +28 % solves. [M]
3. **GPU NN eval, movement-inclusive:** 611 ms → **2.6 ms** per transient
   iteration at 6,144 devices. The unmodified latent path gains ~nothing —
   that is a statement about **one line** (`.tolist()` per device on a CUDA
   slice, §3.3), fixed by a ~10-line single-D2H move (`2a-lite`). Marshalling
   penalty today: 7.7× at 6,144, 22× at 24,576. Irreducible round-trip floor
   56.8 µs/iteration — negligible for arrays, **~6× the work for a single
   cell** (single cells never go to the GPU; batch across circuits = Track B).
   [M, §3.2–3.4]
4. **~52 % of the `.op` solve is per-device Python** (unpack tail + stamping)
   that no GPU touches — vectorise it; the tail vectorises **58×** under the
   §8.1 bit-exactness constraints. Worth ~6.6× on the transient NR loop. [M]
5. **The solver is a first-class transient term** (5.8 h of the 256×128 op
   today): MMD ordering is the one-parameter 76×; KLU-class
   refactorise-not-refactorise is **re-promoted** for ≥64×32 transients
   (~620 factorisations/op, 3×10⁴ per characterisation run, 62,000 per MC
   sweep). [M/E, §5.2]
6. **Parse is demoted** for Track A (amortises), stays first-class for MC
   (parse-once) and returns as ~30 % at end-state. [M/E, §2.6t, §6]
7. **`.ac` is a different regime** — never batched, guaranteed cold
   precompute, **dense** complex matrix per frequency. None of this plan's
   conclusions apply to it; Phase 0 must profile it separately. [M, §5.1]

**End-to-end budget, one 200-step write op** [E, §2.6t — today-columns carry
±40 % from the contended box until Phase 0's quiet re-run]:

| array | devices | today | CPU phases | **+ GPU** |
| --- | ---: | ---: | ---: | ---: |
| 32×16 | 3,072 | ~45 min | ~3.4 min | **~25 s** |
| 32×32 | 6,144 | ~88 min | ~8.2 min | **~50 s** |
| 128×64 | 49,152 | ~12 h | ~50 min | **~8 min** |
| **256×128** | 196,608 | **~2.2 days** | ~7–13 h | **~28 min** |

## Correctness hazards (the ones that bite)

- **Two hard discontinuities sit exactly at the SRAM off-device regime**
  (`id≈0, Vds≈0`): `_guard_gds`'s sign boundary (1 ULP → 5 orders in gds) and
  the wrong-sign clamp (exact 0.0). A float32 reorder can flip a stamp by
  O(1); this is the descendant of the gds sign+floor bug. [§8]
- **§8.1 bit-exactness constraints for the batched tail** (acceptance
  criteria, not guidance): the exponential must be per-element `math.exp`
  over the masked subset (`np.exp` mismatches 4.6 % at 1 ULP, amplified 60×
  by the `1−exp` cancellation at small Vds; `math.sinh` prohibited); cast to
  float64 **before any arithmetic** (NEP-50 keeps float32 → errors up to
  2.2e-7, worse than VNTOL) + dtype asserts.
- **Group membership varies per NR iteration** (`batch_eval` skips
  warm-cached devices): any cached stacked input must key on the actual
  member list, or better use one full-array tensor + per-iteration row
  indices. The 2t fix must ensure the warmed cache contains caps
  (`_require_nn_caps`/`_cache_has_caps`).
- **The MNA sparsity pattern is NOT iteration-invariant today**: the
  `abs(g_mb) > 1e-12` branch drops 4 entries dynamically and `gmb` is clamped
  to exact 0.0 near Vds=0. Any refactorising solver or COO builder must
  either reproduce the dynamic mask or always-emit-zeros (a gated behaviour
  change). [§4.3]
- **`gds` floor before accumulation** in 3b: `max(g_ds, gmin)` per device
  *before* summation.

## Validation regime (condensed §8)

- Bit-identical phases (0,1,2,4a): **byte-identical** full suite
  (`verify_bsimcmg_*`, `verify_subckt` 11/11, `verify_nn_dc_tran`, 16-gate);
  2a additionally a new `verify_batched_tail.py` with exact bit equality per
  element.
- Perturbing phases (2t, 3a, 3b, 4a′) gate **together**, default-off,
  flag-unset path byte-identical in the same run. Tiers: **T0** determinism
  pins (TF32 off — `cudnn.allow_tf32` is True here and must flip;
  `use_deterministic_algorithms(True)`; assert each) · **T1** device-level
  ≤1e-4 rel + **branch-disagreement count** (the physically meaningful
  number) · **T2** solved nodes within the NR tolerance
  `|ΔV| ≤ VNTOL + RELTOL·max|V|` · **T3** 16-gate matrix — `sram_snm` +
  `switchcap` binding (≤0.3 pp, deterministic); `ring_osc`/`opamp` reported
  only (their run-to-run noise exceeds the gate — a GPU 16/16 is *not*
  evidence of fidelity); zero FLIPs binding; Rule-2 canary runs · **T4** new
  `verify_latch_basin_gpu.py`: full 6T latch, both stored states, all techs —
  **100 % same-basin or no promotion** (the suite has no gated bistable test;
  this is the failure mode the plan fears) · **T5** numbers are per-hardware;
  re-run T1/T4 on any driver change. 2t additionally: 16×16 write-transient
  A/B, waveform NRMSE + 100 % latch end-state agreement.
- **Scoreboard discipline:** `docs/accuracy/README.md` stays CPU-only; GPU
  results only in a separate `complex (strict, GPU)` column; evidence in
  `results/v720_gpu_regate/`; *a checkpoint's fidelity is a CPU property* —
  GPU numbers gate the GPU path, nothing else. OMP-strict is redefined on
  GPU as repeat-runs × device-order × CUBLAS-config axes.

## Track B (condensed §9)

Each MC sample is a 200-step transient of a full array. Build: **9a**
parse-once + per-sample perturb + re-solve — requires a **documented device
state reset** (`_eval_cache`, and the transient charge state `_q_prev`,
`_q_prev2`, `_i_prev_*`, `_v_prev_tran`) or samples correlate silently; guard
= re-solve must be bit-identical to a fresh parse of the same perturbed
netlist. **9b** mismatch injection: geometry is a free input column, but
**continuous Vt mismatch has no path into the NN surface today** (Vt is a
categorical embedding row) — blocking for *credible* yield numbers, resolve
first. **9c** process-level parallelism, 3–6 concurrent samples across 3 GPUs
(~3 GB each). Report per-sample retry-rung counts (any pseudo-transient
sample is not a yield result); 5-sample CPU-scalar reference subset; report
the full sorted sample list, not summary stats.
