# V7.0.0 — NN compact-model performance: scan, measurements, routing

**Status:** V7.0.0 = this scan (no behaviour change). Implementation lands as
V7.0.1+, one version per infra change.

Scope: the three NN families (LEVEL=73 DirectNet, 74 BSIM-AR, 75 PFN) share one
inference base (`pycircuitsim/models/mosfet_nn.py`) and one training pipeline
(`external_compact_models/bsimar/`). This document measures both, routes each
lever by whether it can move a gate number, and records the dead ends.

**The governing constraint:** shipped checkpoints and gate results are the
product. A speedup that perturbs the NN surface — even at 1e-8 — can land a
different NR basin in a high-gain circuit (the standing `NN_BATCHED_EVAL=0`
note in `solver.py` exists for exactly this). So every lever below is
classified **bit-identical** (ships default-on) or **perturbing** (ships
default-off behind an env flag, promoted only after a full 16-gate re-gate).

---

## 1. Measurement setup

DirectNet `large` (384 wide × 7 layers, 907,565 params), TSMC5 NMOS
checkpoint, `CUDA_VISIBLE_DEVICES="" torch.set_num_threads(1)` — the gate
configuration. Training numbers on one RTX 4090, 1.6M-row train split,
batch 2048. Raw scripts in the session scratchpad; every number below is
measured, not estimated.

## 2. Inference — where the time goes

Per-eval cost of the shipped path (`_MOSFETNNBase._eval` / `batch_eval`),
single device, batch 1:

| path | µs | note |
| --- | --- | --- |
| forward only | 290 | |
| forward + 1 backward | 784 | |
| forward + 2 backwards | 1233 | |
| **forward + 3 backwards (shipped)** | **1610** | id, qg, qd Jacobians |
| fused analytic Jacobian (one pass, full 13×4) | 748 | perturbing |

Profile of a 70-point NN inverter DC sweep (2.64 s wall): `run_backward`
0.674 s tottime over 1740 calls, `batch_eval` 1.285 s cumtime — i.e. **~50 %
of the whole simulation is the NN eval, and the backward engine is the
single largest line item.**

**Root cause: bandwidth, not FLOPs.** 907k fp32 params = 3.6 MB. One forward
streams that once in 290 µs ≈ 12.5 GB/s — at the single-core memory-bandwidth
ceiling. The shipped path streams the weights **four times** (1 forward + 3
backwards). The FLOPs are trivial (1.8 MFLOP); the traffic is everything.

### I1 — skip the charge Jacobians in DC/OP  *(bit-identical, DC-only)*

`_unpack_eval` always computes `grad_qg` / `grad_qd`, which exist only to
produce `cgg/cgd/cgs/cdg/cdd`. Capacitances are read in exactly two places —
`TransientSolver` (`solver.py:1796`) and `ACSolver` (`solver.py:2603`).
**A `.dc` / `.op` run computes two of three backwards and never reads them.**

1610 → 784 µs = **2.06× on the eval path for every DC analysis** (inverter
VTC, the 55-case DC gate, SRAM SNM, opamp DC gain). Bit-identical: the
skipped values are not inputs to anything the DC solver stamps. Transient/AC
are unaffected (they genuinely need the caps every NR iteration).

Needs a cache-mode tag so a cap consumer arriving at a DC-warmed cache
recomputes rather than reading absent keys.

### I2 — fused analytic Jacobian  *(perturbing → opt-in)*

DirectNet is a plain MLP, so the Jacobian can be propagated forward in closed
form alongside the value: stack `[h ; ∂h/∂v]` as (5, dim) and issue **one**
GEMM per layer. One weight stream instead of four, and it yields the full
13×4 Jacobian (today's path gets 3 rows of it).

Measured 1610 → 748 µs = **2.16× at N=1**, decaying to 1.13× at N=32 (large
groups already amortize the weight stream).

Not bit-identical: values differ ~4.8e-7 abs, `∂id/∂V` ~4e-6 relative — same
math, different summation order. Ships behind `PYCIRCUITSIM_NN_FUSED_JAC=1`,
default off, promoted only on a clean 16-gate re-gate.

> **Correction after implementing V7.0.1 — I2's scope is narrower than the
> 2.16× headline.** That figure compares against the *old* 3-backward path.
> Once I1 has removed the two charge backwards, a DC eval costs 784 µs and
> the fused pass costs 748 µs — the fused pass computes the whole 13×4
> Jacobian whether or not the caps are wanted, so it cannot exploit
> DC-mode. Measured end-to-end on the inverter decks: **DC 1.48 s → 1.64 s
> (slightly slower), transient 3.04 s → 2.20 s (1.38× faster)**. I2 is
> therefore a **transient/AC lever only**, and I1 is strictly better for DC.
> Deviation on the inverter is small (max |ΔV| = 7e-7 DC, 4e-7 transient),
> but the inverter is the benign case — the opamps are what a re-gate has
> to clear.

### I3 — Python-side per-eval overhead  *(bit-identical)*

Small but free, and it applies to every analysis:

- `_stats_col()` does a `list.index` per scalar, 13× per eval, to rediscover
  constants fixed at construction.
- `_denorm` / `_denorm_deriv` call into the normalizer per scalar, each
  re-reading numpy arrays and re-boxing floats.
- `solver._mosfet_types()` / `_nn_mosfet_types()` / `_pmos_types()` re-import
  modules and rebuild their tuples on **every call** — 4462 + 2596 calls in a
  70-point sweep (~0.05 s).
- `_prep_voltages` builds a fresh tensor from a Python list per eval.

Worth ~4 % of the DC sweep. Precompute at `__init__`, memoize the type tuples.

### I4 — LEVEL=74 AR prefix cache  *(exact in ℝ, NOT bit-identical → opt-in)*

`TransformerEncoderModel.forward`'s inference branch re-runs the **entire
encoder over the whole growing prefix, 8 times** (`transformer.py:284`), with
no KV/hidden-state cache. Under a causal mask the prefix hidden states cannot
change once computed, so caching them is exact in exact arithmetic — the
recompute is pure waste, and it is the reason BSIM-AR is 30–100× slower than
DirectNet. Estimated 3–4×; must be verified bit-wise before it ships default-on,
since SDPA kernel shape changes can perturb the last bits.

> **Implemented and measured 2026-07-25 (V7.0.4). The bit-wise verification
> came back NEGATIVE, and the cause is a hard floor rather than a fixable
> detail — so I4 ships default-off like I2, not default-on.**
>
> `_encoder_append` streams each token through the stack once, keeping
> per-layer K/V so the new token still attends to the whole prefix: 60
> token-passes → 11. Delivered **1.60× DC / 1.56× transient / 1.21× AC**
> end-to-end, behind `PYCIRCUITSIM_NN_AR_CACHE=1`.
>
> **Why it is not bit-identical: `F.linear` is not row-stable on this CPU.**
> A 1-row GEMV accumulates in a different order than the same row of an
> L-row GEMM — measured **0/96 shapes stable**, up to 8e-6 abs. Any
> formulation that computes fewer rows than the stock recompute therefore
> moves the last bits, no matter how attention is arranged. This kills the
> obvious rescue too (cache Q/K/V, replay the *identical* full-prefix SDPA
> call, shrink only the projections): attention is ~1 % of the cost here,
> but the projections that carry the other 99 % are exactly the rows that
> cannot be shrunk exactly. Measured deviation on shipped checkpoints:
> outputs ≤ 5.3e-6, autograd Jacobians ≤ 1.6e-6, solved node voltages
> ≤ 1.6 µV.
>
> **Why the speedup is 1.6× and not the 5.45× the token count suggests.**
> Like DirectNet, the encoder is weight-bandwidth-bound, and the weight
> stream is paid **per encoder call, not per token** — 8 AR steps means 8
> streams of the whole 1.77 MB/layer either way. The cache removes the
> *arithmetic* on the redundant tokens (roughly half the cost at batch 1),
> not the traffic. The 8 sequential streams are irreducible: that is the
> autoregressive data dependence itself.
>
> **Two findings worth keeping:**
> - `nn.TransformerEncoder` runs `_detect_is_causal_mask` on the mask it is
>   handed and forwards `is_causal=True` to SDPA with `attn_mask=None`, so
>   the stock call reaches the *fused causal* kernel. Rebuilding the same
>   mask explicitly selects the math kernel and shifts the primer by 7e-7
>   for nothing. `_encoder_append` matches the hint.
> - `TransformerEncoderLayer.forward` has a second fused fast path
>   (`torch._transformer_encoder_layer_fwd`, one whole-sequence kernel)
>   that fires **only under `no_grad`** — PyTorch disqualifies it whenever
>   grad is enabled and a parameter requires grad, since the fused op is not
>   differentiable. Every simulator eval wraps the forward in
>   `torch.enable_grad()` for the Jacobian, so the shipped LEVEL=74 surface
>   has never used it. It does serve the trainer's `no_grad` AR test
>   metrics, where the cache is nevertheless **4.3× faster at batch 2048**
>   (5563 → 1291 ms) because that regime is genuinely FLOP-bound.

### I5 — thread count  *(rejected)*

Forward drops 282 → 182 µs at 4 threads, but gates deliberately pin
`OMP_NUM_THREADS=1` and torch to 1 thread. Not a lever to touch here; the
V6.13.0 gds fix removed the OMP flips, but re-opening thread count is a
gate-policy decision, not an infra change.

## 3. Training — where the time goes

Per optimizer step, DirectNet large, batch 2048:

| config | ms/step | s/epoch @1.6M rows | cumulative |
| --- | --- | --- | --- |
| **shipped** `DataLoader(TensorDataset, num_workers=8, pin_memory)` | 11.00 | 8.6 | — |
| GPU-resident index slicing | 3.29 | 2.6 | 3.3× |
| + `AdamW(fused=True)` | **1.77** | **1.4** | **6.2×** |

### T1 — GPU-resident batching  *(no effect on shipped checkpoints)*

`_train_loop` wraps already-in-memory tensors in a `TensorDataset` and hands
them to a `DataLoader` with 8 worker processes. For tabular data that means
2048 individual `__getitem__` calls, a collate, and an IPC copy **per batch**,
to deliver something that is one contiguous slice of a tensor that already
exists. The whole TSMC5 train split is 1.6M × 34 floats = 218 MB — it fits on
the GPU with room to spare (24 GB cards).

Replacing the loader with a permutation + index slice on-device: 11.0 → 3.3
ms/step. Same for the per-epoch val/test loaders.

### T2 — fused AdamW  *(no effect on shipped checkpoints)*

3.29 → 1.77 ms/step. At this model size the step is launch-overhead-bound, so
folding the optimizer into one kernel is the single biggest remaining win.

### T3 — per-step `loss.item()`  *(no effect on shipped checkpoints)*

`_epoch_train` syncs the GPU every batch to accumulate a scalar it only prints
once per epoch (~800 syncs/epoch). Accumulate on-device, sync once.

**Checkpoint-safety note:** T1–T3 change the *shuffle order* and therefore
produce different weights on a **re-train**. They do not touch any checkpoint
on disk, so no gate moves until someone retrains. The old path stays available
as a fallback for reproducing a historical run.

## 4. Dead ends (measured, rejected — do not retry)

- **TF32** (`allow_tf32=True`): 1.77 → 1.92 ms/step. *Slower.* The model is
  launch-bound, not matmul-bound; TF32 only adds conversion work.
- **`torch.compile`**: 1.77 → 2.00 ms/step. Guard overhead exceeds the fusion
  win at this size. (Still worth re-testing for the Transformer/PFN families,
  which are genuinely compute-bound.)
- **bf16 autocast on DirectNet**: 1.77 → 2.61 ms/step. *Worst of all* — cast
  traffic on a bandwidth-trivial model.
- **Replica-batch trick for the 3 inference gradients** — replicate the input
  3× and take one backward with a column-selecting seed. Only 1.53× (vs 2.16×
  for the analytic Jacobian) **and** not bit-identical (GEMV→GEMM changes the
  summation order: grads differ 4e-6 at N=1, 1.8e-4 at N=10). Strictly
  dominated; do not revisit.
- **Larger training batch** (8192/16384) is a *recipe* change, not infra — it
  needs LR rescaling and would invalidate every recipe comparison. Excluded
  deliberately, despite being the largest raw number on the board (0.43
  s/epoch).

## 5. Routing

| --- | --- | --- | --- | --- |
| V7.0.1 | I1 DC charge-Jacobian skip + I3 Python overhead | bit-identical | 2× on DC | **1.68× DC solve; 3/3 CSVs sha256-identical** |
| V7.0.2 | T1 + T2 + T3 training loop | checkpoint-neutral | ~6× per epoch | **4.9× (3.4 → 0.7 s/epoch, real CLI)** |
| V7.0.3 | I2 fused analytic Jacobian (`PYCIRCUITSIM_NN_FUSED_JAC=1`) | perturbing, default-off | 2.16× all analyses | **1.38× transient/AC only** (see correction above) |
| V7.0.4 | I4 AR prefix cache (`PYCIRCUITSIM_NN_AR_CACHE=1`) | **perturbing, default-off** (routed as exact; refuted) | est. 3–4× on BSIM-AR | **1.60× DC / 1.56× tran / 1.21× AC; 4.3× on `no_grad` batch eval** |

Verification gate for V7.0.1: DC sweep, transient and AC CSVs must be
**sha256-identical** to the pre-change baseline. Anything perturbing is
default-off until a full 16-gate re-gate is run and recorded.

### Verification actually run (2026-07-25, V7.0.1 + V7.0.2 + V7.0.3-off)

- DC / transient / AC CSVs: **sha256-identical** to the pre-change baseline,
  both before and after the V7.0.3 code landed (flag off).
- `verify_nn_dc_tran --tech TSMC5 --inverter-only`: 2/2 PASS (VTC 1.04 %,
  inverter transient 0.97 %).
- `verify_nn_ac`: **8/8 PASS**.
- `verify_complex_ring_osc`: **4/4 PASS** (period error 2.40–4.04 %).
- `verify_bsimcmg_op` 3/3, `verify_bsimcmg_dc` 2/2, `verify_bsimcmg_tran` 1/1,
  `verify_subckt` **11/11** — the L72 path is untouched by the solver edits.
- Training smoke: DirectNet / Transformer / TabPFN all train through the new
  loader; `BSIMAR_LOADER=torch` reproduces the legacy path.

**Not run** (needed before V7.0.3 could ever be promoted): the full 16-gate
complex matrix across OMP∈{1,2,4}, and the 55-case NN DC / 64-case tran
sweep. V7.0.1/V7.0.2 do not need them — V7.0.1 is byte-identical and V7.0.2
does not touch a shipped checkpoint.

### Verification actually run (2026-07-25, V7.0.4 AR prefix cache)

Flag **off** (the shipped default) — proves zero regression:

- LEVEL=74 TSMC5 DC / transient / AC CSVs **sha256-identical** to the
  pre-change baseline (stashed-source run), all 3 of 3.
- `verify_bsimcmg_op` 3/3, `verify_bsimcmg_dc` 2/2, `verify_bsimcmg_tran`
  1/1, `verify_ac` 2/2, `verify_subckt` 11/11.
- DirectNet LEVEL=73 `verify_nn_dc_tran --inverter-only` over all four
  techs: **8/8 PASS** (avg VTC NRMSE 1.07 %) — unchanged.

Flag **on** — measures the lever:

- LEVEL=74 TSMC5 inverter gate vs NGSPICE (`PYCIRCUITSIM_NN_FORCE_LEVEL=74`,
  resolved to `tsmc5_tf_large_{nmos,pmos}`): **2/2 PASS with identical
  scores** — VTC 1.09 %, inverter transient 0.97 % — under both flag states.
  The 1.6 µV perturbation is orders of magnitude below gate resolution.
- End-to-end wall clock, 1 thread, TSMC5 `tsmc5_tf_large_*`:
  DC 33.2 → 20.8 s (**1.60×**), transient 120.6 → 77.5 s (**1.56×**),
  AC 8.8 → 7.3 s (**1.21×**).
- Per-eval, DirectNet-comparable units (`corroft@medium`, batch 1):
  DC (fwd+1bwd) 43.5 → 27.2 ms, transient/AC (fwd+3bwd) 83.0 → 54.7 ms.
  Gains grow with device count: at batch 4 both modes reach **2.06×**.

**Not run** (needed before `PYCIRCUITSIM_NN_AR_CACHE=1` could be promoted to
default-on): the full 16-gate complex matrix at `MODEL=transformer` across
OMP∈{1,2,4}. The bar is the same as V7.0.3's, and for the same reason — the
opamps, not the inverter, are what a perturbing lever has to clear.
