# V6.7.0 — Universal DirectNet + TSMC5 Transfer Study

**Date:** 2026-07-05 · **Branch:** V6.6 · **Status:** COMPLETE (all phases incl. 1b xl arm).
**Plan / execution log:** `docs/plans/2026-07-02-universal-nn-tsmc5-transfer.md` · **Raw evidence:** `results/uni_bench/`
**Production impact: NONE.** All artifacts use `u716_*` / `u716f5_*` stems, reachable only via explicit
`PYCIRCUITSIM_NN_CHECKPOINT_DN_{NMOS,PMOS}` pin; the per-tech resolver cascade is untouched.

## 1. TL;DR

1. **Universal is viable.** ONE 18-code-embedding DirectNet (`large`, ~7M rows, TSMC16+12+7) matches per-tech
   device fidelity (id NRMSE ≤0.09% per variant, R² ≥0.996) and — with the corridor curriculum — **ties the
   per-tech complex-gate calibration bar: corroft = 10/12 strict**, with **zero OMP flips** (per-tech `large`
   never achieved full determinism).
2. **The corridor is the ring lever at universal scope too**: it fixes tsmc7-ring (14.89% → 3.61% period error)
   in both curricula. The inv_trip anchor (crit30u) again *relocates* rather than composes — it degrades
   tsmc12-opamp from det-PASS to a FLIP. csob's per-tech tsmc16-opamp basin does **not** survive the scope
   change. Basin relocation (V6.6.7 lesson) generalizes: **recipe → basin maps are scope-dependent, not just
   tier-dependent.** The xl arm completes the picture: clean@xl banks tsmc12+16 opamps but loses all rings;
   corroft@xl restores rings but rails all opamps — the mutual-exclusive-basin wall at universal xl is
   partitioned opamps-XOR-rings, and 11/12 is unreached at both tiers (§7).
3. **TSMC5 onboarding costs ~1M rows (≈half the per-tech dataset): `plain@n1M` = 4/4 TSMC5 gates STRICT** —
   including the opamp — matching the per-tech production bar (crit30f: 4/4 strict). The gate threshold is
   sharp: 0/4 at every tier ≤200k. Device-level: n10k *diverges* (normalizer refit), n200k ~6–10% DC NRMSE,
   n1M 0.6–0.7%, full 0.4–1.1%.
4. **No free retention.** TSMC5-only fine-tuning collapses the source techs at gate level (1–3/12 retained;
   TSMC12 DC NRMSE 18–23% at heavy tiers, one outright blow-up). Forgetting damage is high-variance.
   Universal-base fine-tuning is a cheap **onboarding** path, not a **multi-tech serving** path — serving all
   techs from one checkpoint means using the universal base itself (10/12), and per-tech checkpoints remain
   the accuracy frontier for TSMC5 (4/4 needs the fine-tune, which then *is* a per-tech model).

## 2. Methodology

- **Data:** `uni716_{dev}.npz` = concat of tsmc{7,12,16} per-tech sets (nmos 6,920,730 / pmos 7,256,992 rows;
  `_corro` variants ~+27k rows), built by `scripts/uni_concat_npz.py` (validated: row sums, sidecar code
  ranges 4–16, class histograms, 100/100 spot rows bit-identical). TSMC5 tiers by `scripts/uni_subsample_npz.py`
  (stratified by `sample_class`, seed 42 — n2000 keeps traj_corridor=9, inv_trip=67).
- **Training:** `scripts/uni_ft_train.sh` / `scripts/uni_train.sh` → `bsimar.cli.train --tech-scope universal
  --size large --apply-filter off --swa-mode ema --seed 42`; curricula warm-start from the u716 clean base
  (`--lr 3e-4 --epochs 120 --patience 40`), never from another curriculum. Completed runs carry `.complete`.
- **Gating:** `scripts/uni_gate_sweep.sh` — identical conventions to `results/recipe_bench/ACCURACY_REPORT.md`:
  CPU-pinned cells, strict = identical verdict at `OMP/MKL/PYCIRCUITSIM_TORCH_THREADS ∈ {1,2,4}` (opamp+ring
  sweeps; SRAM/SC deterministic), FLIP = unbankable fail, tsmc7-opamp = known-fail (excluded from opamp means),
  per-cell `[NN-resolver] … scope=universal` post-check (any miss → RESOLVER-MISS, campaign-invalid).
  **Zero RESOLVER-MISS across all 200 cells.**
- **Calibration bar (per-tech, same 12 gates):** clean / crit30f / csob / corroft all = 10/12 strict, differing
  only in which opamp cells they bank; 11/12 (all but tsmc7-opamp) = realistic ceiling.

## 4. TSMC5 sample-efficiency (fine-tune from u716 clean base, `u716f5_{plain,crit}_n{N}`)

**Gates (4 TSMC5 complex circuits, single-run; strict where swept):**

| tier N | plain | crit |
|---|---|---|
| 2k / 10k / 50k / 200k | 0/4 | 0/4 |
| 1M | **4/4 — STRICT (OMP 1/2/4)** | 1/4 (ring only) |
| full (~2.02M) | 3/4 (opamp det-FAIL) | 3/4 (opamp FAIL) |

**Device level (DC NRMSE %, nmos / `verify_nn_dc_tran` TSMC5):**

| tier | plain | crit | note |
|---|---|---|---|
| 2k | sweep unusable (N/A) | N/A | model wrecked by norm refit on 1.8k train rows |
| 10k | ~1e69 (DIVERGED) | ~1e69 | normalizer-refit failure mode, not noise |
| 50k | 35.1 (ERROR) | 35.1 (ERROR) | |
| 200k | 10.1 FAIL | 5.9 PASS | crit's class weights help at moderate N |
| 1M | 0.69 PASS | 0.57 PASS | |
| full | 0.42 PASS | 1.08 PASS | pmos full: 0.64 / tran 0.52 / inv-tran 1.27 (plain) |

- **The gate threshold (200k→1M) lags the device threshold** — 5.9% DC NRMSE (crit@200k, device-PASS) is
  nowhere near enough for complex gates; the value surface needs the ~1M-row tightening.
- **n1M > nfull at gates** (plain: 4/4 vs 3/4, opamp det-FAIL at full) — non-monotone in N; more TSMC5 data
  shifted the opamp basin *out*, the same whack-a-mole seen across recipes. The n1M opamp hold is
  deterministic, so it *is* bankable, but tier selection is itself a basin lottery.
- `crit` fine-tune ≠ better: better 200k device metrics, worse n1M gates (1/4). The curriculum weights do not
  compose with the transfer setting any better than they compose across scope.
- TSMC5 AC: PASS only at the full tier (both recipes).
- Zero-shot (untrained embedding rows 0–3): 0/4 gates, as expected — no free lunch from the shared trunk alone.

**Device level (DC NRMSE %, nmos, TSMC12 shown — worst tech):**

| tier | plain | crit |
|---|---|---|
| 2k | 5.8 PASS | 5.8 PASS |
| 10k | 7.9 PASS | 7.8 PASS |
| 50k | 11.0 FAIL | 10.1 FAIL |
| 200k | 17.5 FAIL | 23.0 FAIL |
| 1M | **26,424 FAIL (blow-up)** | 5.9 PASS |
| full | 18.0 FAIL | 23.0 FAIL |

**Gate level (12 retention gates, plain):** n1M keeps 1/12 (tsmc7-SRAM); full keeps 3/12 (tsmc7-SRAM/SC,
tsmc16-SRAM). TSMC16 ~10%, TSMC7 ~5.5% DC NRMSE at full (marginal).

- Forgetting grows with fine-tune N and is **high-variance** (plain@n1M destroys TSMC12 while crit@n1M retains
  it at 5.9% — luck, not structure). Without replay, the fine-tune converts the universal model into a de-facto
  per-tech model. A replay-mix arm (e.g. 10% source-tech rows) is the obvious follow-up; out of scope here.

## 7. Phase 1b — xl arm: tsmc16-opamp IS reachable, but only by trading ALL rings

| recipe@xl | strict | FLIPs | detail |
|---|---|---|---|
| clean@xl | 8/12 | 1 | **banks tsmc12-opamp (5.55%) AND tsmc16-opamp (6.41%) det-PASS** — the `large` tsmc16 rail is tier-local — but ALL rings fail (tsmc7 13.36% / tsmc12 7.00% det-FAIL, tsmc16 5.19% FLIP) |
| corroft@xl | 8/12 | 0 | corridor holds rings 3/3 (tsmc7 4.76%) but ALL opamps rail (tsmc12 gain err 100%, trip shift 146 mV) and tsmc7-SC drops (charge 2.15% of VDD). Per-tech corroft@xl's tsmc16-opamp bank does NOT transfer. Curiosity: tsmc7 AC PASS — the campaign's only AC pass. |

The Phase 1b question is answered **negatively for the ceiling**: the tsmc16-opamp basin exists at universal
xl (clean@xl proves it deterministically), but the corridor curriculum — needed for the rings — relocates it
away. The V6.6.1 mutual-exclusive-basin wall reappears at universal xl, partitioned **opamps-XOR-rings**.
11/12 is not reached at either tier; **corroft@large (10/12 strict, 0 FLIPs) stands**. Third independent
demonstration (after tier and scope) that curriculum weight→basin maps do not transfer across the
capacity/scope axes. (xl zero-shot SRAM cells TIMEOUT at 2700 s — xl CPU inference is slower; diagnostic
lane only.)

## 8. Recommendation

- **Best universal recipe: `corroft` @ `large`** (`u716_dn_corroft_large_{nmos,pmos}`) — 10/12 strict,
  0 FLIPs, per-tech-parity. The xl arm does not displace it: xl banks the tsmc16-opamp only by trading every
  ring (§7).
- **New-tech onboarding recipe:** universal clean base + plain fine-tune at ~1M stratified rows → 4/4 strict
  complex gates on the new tech at half the per-tech data cost. Do NOT expect the result to serve the source
  techs (§5); treat it as an accelerated per-tech checkpoint.
- **No production promotion** proposed: per-tech crit30f@large (14/16) remains production; the universal
  model's value is (a) the onboarding path, (b) one-checkpoint multi-tech serving at 10/12 where that
  trade-off is acceptable.

## 9. Dead ends (recorded per workflow rule)

1. **csob at universal scope** — worst of the four (8/12 + FLIP); its per-tech tsmc16-opamp basin is
   scope-local. Charge-axis benefits (halved q-errors) persist, so it remains the charge/AC-fidelity alternate.
2. **crit30u (anchor) at universal scope** — anchor relocates the tsmc12-opamp basin into a FLIP; corridor-only
   is strictly better here. Third independent confirmation (after tier and base-swap) that the anchor's
   weight→basin map does not transfer.
3. **`crit` fine-tune for transfer** — better mid-tier device metrics, worse gate outcome at the tier that
   matters (n1M 1/4 vs plain 4/4).
4. **Tiny-tier fine-tunes (≤10k)** — diverge outright via the tier-refit normalizer (§7 caveat of the plan,
   confirmed as divergence, not noise). Any few-shot regime below ~50k rows needs a frozen normalizer
   (pipeline change, out of scope).
5. **Zero-shot TSMC5 from the universal trunk** — 0/4; embedding rows must be trained.
