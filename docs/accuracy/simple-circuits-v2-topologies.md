# Simple-circuit topology evaluation

This document defines the held-out `simple-v2` evaluation set for NN compact
models. They exercise device composition more deeply than a single transistor
or inverter while remaining inside the compact-model qualification scope.

The existing four-cell score is versioned as `simple-v1` and remains `/20` per
tier. `simple-v2` is diagnostic until its reference stability and thresholds
are frozen; no exploratory result in this document is a published score.

## Difficulty ladder

Cases are ordered by how much of the answer the deck supplies, not by device
count. Each case declares its `tier`, which is verified against the template's
location under `circuit_templates/`. The rungs are defined in
[`circuit_templates/README.md`](../../circuit_templates/README.md).

### L1 — one active device on a passive load

| case | analyses | behavior exposed beyond pointwise device error |
|---|---|---|
| `common_source_nn` | fixed/floating-bulk NMOS/PMOS AC | output pole plus dynamic bulk response |
| `source_follower` | NMOS/PMOS DC | body effect, source-relative lifting, gain and rail approach |
| `common_gate` | NMOS/PMOS DC | source-driven bias, transconductance and signed input current |
| `diode_load` | OP, up/down supply and low/high-impedance DC | load-line intersection, continuation direction, MOS-referenced voltage, and line sensitivity without a duplicate campaign case |

### L2 — coupled devices, every gate rail from an ideal source

| case | analyses | behavior exposed beyond pointwise device error |
|---|---|---|
| `inverter_energy` | VTC and supply-current transient | trip, leakage, delay, and switching energy |
| `transmission_gate_dc` | forward/reverse DC | complementary conduction, bidirectionality and on-resistance |
| `current_mirror` | NMOS/PMOS compliance DC, NMOS/PMOS reference-current DC | mirror ratio, compliance, output resistance, and ratio accuracy from subthreshold to strong inversion |
| `inverter_chain` | transient | open-chain FO4 loading, delay, rise/fall, amplitude and phase-aligned shape |
| `diffpair_ideal` | steering DC, differential/common-mode AC | current steering, differential versus common-mode gain, and CMRR with an ideal tail |
| `diffpair_active` | steering DC, differential/common-mode AC | the same observables with device-device tail interaction |
| `cascode_stack` | NMOS/PMOS compliance DC, AC | stacked-device bias, internal nodes and output resistance |
| `nand2` | both input DC paths, transient | series NMOS stack, internal-node history, trip and delay |
| `nor2` | both input DC paths, transient | series PMOS stack, internal-node history, trip and delay |
| `sram_snm` | forced-input read-SNM DC | three coupled device currents; no closed latch state is supplied by this half-cell |

### L3 — internal bias generation or internal state

| case | analyses | behavior exposed beyond pointwise device error |
|---|---|---|
| `transmission_gate_hold` | transient | charge hold, off-state droop and clock feedthrough |
| `sram6t_modes` | both-state hold/read/write transient and both write-margin directions | cross-coupled feedback, symmetry, read disturb, write time, retention, and regenerative trip points |
| `opamp_rejection` | differential/common-mode/supply AC | CMRR and PSRR, formed from a pair of AC experiments |
| `switchcap_multicycle` | 10-period transient | charge error accumulated over cycles rather than sampled once |
| `ring_osc_supply` | transient | oscillation period plus dynamic supply current, run across the supply corners |
| `diffpair_active_load` | NMOS/PMOS OP and AC | role-sized input pairs, internally generated mirror bias, internal nodes, gain, and bandwidth |
| `beta_multiplier` | supply-ramp DC | constant-gm self-bias: which of two DC solutions the model selects, and at what supply it leaves the degenerate one |
| `self_biased_cascode` | compliance DC | the paired experiment to `cascode_stack`, with the cascode rail generated by devices instead of ideal sources |
| `bias_tree_fanout_{3t,5t,9t,17t}` | explicit OP topology at each scale | isolate coupled-network scale while holding the generated-bias question fixed |

### L4 — closed negative-feedback systems

| case | analyses | behavior exposed beyond pointwise device error |
|---|---|---|
| `unity_gain_buffer` | closed-loop DC, step settling, AC | loop solution, settling, bandwidth, and peaking of the Miller opamp |
| `ota_5t_buffer` | closed-loop DC, step settling, AC | the same, with the tail bias generated on chip |
| `ldo_regulator` | line DC, load transient, PSRR/output-impedance AC | seven coupled MOSFETs with all bias internal |
| `multistage_buffer_12t` | cold-start settling and closed-loop AC | first production-shaped rung above ten MOSFETs; buffered feedback, bandwidth, and basin entry |

Every L4 case declares at least one transient **without** `uic`, and the
catalog contract check enforces it. Every other transient in this catalog is
handed its initial state through `.ic`, so the cold-start path — solving a DC
operating point before integrating — is exercised only here.

Every case declares its expected signals and domain metrics in
`tests/common/simple_circuit_catalog.py`. DC, transient and AC are all present;
current signals keep their sign rather than being converted to magnitudes.

### Cross-analysis metrics

A rejection ratio is a property of a pair of experiments, so it cannot come
from the per-analysis metric path. Cases naming `derived_metrics` get one
extra `analysis="derived"` result row that combines the gains their AC sweeps
produced: `cmrr` from the differential and common-mode gains, `psrr` from the
differential and supply gains. If any input is missing — because its sweep
errored — the derived row is itself an `ERROR` rather than a silent omission.

### Unconverged rows

A DC row that does not converge stays an `ERROR`: it never becomes a pass and
never enters a numeric aggregate. It does, however, carry an
`unconverged_diagnostic` payload holding the metrics from a single repeat run
without the convergence requirement. "Did not converge" and "was 200 mV out"
are different facts about a model, and no scoring path reads that payload.

## Unified-template contract

Each experiment has one `.spice.tmpl` source in `circuit_templates/`.
The candidate and LEVEL=72 reference adapters render it with different compact-
model binding and engine-required syntax while preserving components,
connectivity, sources, initial conditions, and analysis limits. Rendering is
strict: missing and unused tokens are errors. Before either simulator runs,
the harness compares a canonical topology signature, including MOS polarity
and terminal order, source kind, and initial conditions.

The legacy opamp, ring oscillator, SRAM-SNM and switched-capacitor builders,
plus the scored inverter VTC/transient builders, now render these authoritative
templates as well. The ring stage-count sweep selects explicit 3-, 5-, 7-,
and 9-stage templates and parity-checks every declared topology.

## Corner matrix

The default diagnostic is nominal. The declared stress matrix adds:

- `temp_cold` at −25 °C and `temp_hot` at 125 °C;
- `vdd_low` at 0.85× nominal and `vdd_high` at 1.10× nominal;
- `body_reverse` at 0.10×VDD reverse body bias through explicit body rails in
  every applicable simple-v2 deck;
- `pn_n3p2` and `pn_n2p3` fin-ratio asymmetry;
- `joint_hot_lowvdd`: 125 °C, 0.90×VDD, LNMOS=LPMOS=20 nm,
  NFIN-N=3 and NFIN-P=2.
- `vt_alternate` and `vt_asymmetric`, selected from each technology's trained
  local vocabulary;
- independent `ln_20`, `lp_16`, and symmetric `nfin_high=5` geometry stresses.

Applicability is evaluated per analysis and observed device polarity. A
technology without the requested VT/L bin, a body corner on a rail-tied deck,
or a P-only fin change in an N-only analysis creates no row rather than a
duplicate nominal denominator slot.

The older parametric four-circuit sweep also exposes `temp` and `joint`
dimensions so qualification and diagnostic campaigns share these stress axes.
The dataset-geometry guard derives the unique L/NFIN/temperature requests from
the catalog and checks that the corresponding training grid and PDK bin exist.
Voltage and body-bias support is assessed separately from accepted LEVEL=72
trajectories.

## Harness and campaign flow

`tests/common/simple_circuit_harness.py` provides an engine-neutral `Trace`,
multi-signal OP/DC/transient/AC adapters, interpolation, aggregate MRE/R²/NRMSE/
maximum error, domain metrics, reference-repeat stability and support
diagnostics. `--level72-control` also runs the identical deck through
PyCircuitSim LEVEL=72; NGSPICE remains the only reference. Support is computed
only from accepted LEVEL=72 physical node
trajectories in the source-relative terminal frame; candidate Newton trial
overshoot is never classified as a dataset gap.

Run a subset directly:

```bash
conda run -n pycircuitsim python \
  tests/simple_circuits/verify_circuit_topologies.py \
  --case current_mirror,inverter_chain --tech TSMC5 --corner nominal
```

Use `--case all --corner all` for the declared matrix and
`--reference-repeats 3` when gathering promotion evidence. Results go under
`results/tests/simple_circuits/simple-v2/` by default and every requested
analysis emits a structured marker. An `ERROR` stays in the denominator while
numerical aggregates include only characterized rows.

`verify_terminal_integrity.py` reuses `L0_devices/mosfet.spice.tmpl` to collect
all four terminal currents and form a physical 4x4 transcapacitance matrix from
four AC excitations. `verify_nn_subckt.py` compares flat and nested NN buffers
against one LEVEL=72 reference for LEVEL=73–76.

For checkpoint campaigns, `scripts/v710_regate_jobs.py` writes a separate
nominal-corner `jobs_simple_v2.txt` screening pool. Full corner characterization
uses the unified CLI's `--corner all` mode. The shell driver maps catalog suite
IDs to the unified CLI, the collector stores structured results, and
`scripts/v730_coverage.py --simple-version simple-v2` audits coverage. The
default coverage mode remains `simple-v1`, preserving historical reports.

## Promotion rule

Do not fold these diagnostics into `simple-v1`. Create a new score version only
after all of the following are true:

1. LEVEL=72 produces three repeatable, complete traces at every proposed cell.
2. Each gate answers one declared question with a frozen threshold and unit.
3. The exact case/technology/corner/analysis denominator is immutable.
4. Candidate and reference topology parity, artifact completeness, checkpoint
   hashes, commit and CPU thread settings are recorded in one campaign.
5. No partial logs or infrastructure failures are treated as scientific
   passes or silently removed from the denominator.
