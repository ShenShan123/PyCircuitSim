# V6.9.0 — TSMC6 (CLN6) Onboarding + TSMC PDK Parse Audit

**Date:** 2026-07-12 · **Branch:** `feat/tsmc6-onboarding` (main repo + PyCMG submodule)

Two deliverables in one campaign: (1) onboard the TSMC N6 iPDK model card
(`cln6_1d8_sp_v1d0_2p2.l`, BSIM-CMG level=72 version=106.1, 0.75 V core) as the

(TSMC5/6/7/12/16), quantifying every simplification the naive-modelcard
pipeline applies.

## Part I — TSMC6 onboarding

### The N6 card is a structural clone of N7 — but not a numerical copy

- Identical `.lib` section set (202 names), identical `.model` name set
  (278 cards), identical binning scheme and directive counts vs
  `TSMC7/cln7_1d8_sp_v1d2_2p2.l`. Zero parser grammar changes were needed.
- **153 of 204 core svt/lvt/ulvt `.model` blocks are byte-identical to N7**
  (TSMC copied the N7 v1d2_2p1 models per the card's release notes). The 51
  differing blocks include every `.global` block, every `.30` bin, and most
  `pch_ulvt`/`pch_lvt` bins — so the tech is genuinely (mildly) different:
  the generated datasets differ from tsmc7's (md5-distinct npz).
- Consequence for NN data: the 12-parameter process fingerprint used by the
  dataset labeller is **identical for every (bin, L, NFIN)** — 108/108 nmos
  fingerprints collide tsmc6↔tsmc7 (audit finding #1 below).

**Code-stability invariant (now documented in `bsimar/config.py`):** universal
tech codes are baked into every trained checkpoint's embedding rows and every
dataset's `*_tech_variant_labels.npy` sidecar. New techs are appended at the
TAIL of the ordering (after ASAP7); inserting into the legacy TSMC block would
renumber codes 4+ and silently corrupt all existing checkpoints and sidecars.
The legacy constants (`UNKNOWN_CODE_ID=17`, `NUM_TSMC_CODES_WITH_UNKNOWN=18`)
are unchanged, so every existing per-tech and universal checkpoint loads
identically.

## Part II — TSMC PDK parse audit (all 5 cards)

**Tool:** `external_compact_models/PyCMG/scripts/audit_pdk_parse.py`
(kept in-tree; registry-driven, reusable for future cards). For every
(tech × device × bin) it classifies every assignment in the raw `.global` +
bin `.model` blocks, round-trips the naive card against the merged raw
parameters, checks bin-boundary selection, and cross-references the OSDI
descriptor's parameter set.

**Headline: AUDIT PASS — 40 device audits (5 techs × 6–10 devices), 0
round-trip mismatches, 0 errors.** Every parameter in every generated naive
card equals the merged (variant-overrides-global) raw value, modulo the three
documented transforms (instance-param exclusion, TSMC ±999·10ⁿ sentinel drop,
EOTACC ≤1e-10 → 1.1e-10 clamp).

### Findings

1. **[FIXED — the one real defect] Dataset labeller fingerprint collision.**
   `bsimar/eval/loo_labels.py` labelled rows by a `(NFIN, L, 12 process
   params)` fingerprint with silent last-writer-wins across techs. TSMC6's
   N7-copied bins make **every** tsmc6 fingerprint collide with tsmc7
   (108/108 measured for nmos): adding tsmc6 to the scan would have silently
   mislabelled tsmc7 (or tsmc6) training data. Fix: per-tech datasets are
   labelled against their own tech only (`tech_filter` inferred from the
   `<tech>_<device>.npz` stem); the universal no-filter scan keeps the legacy
   5-tech order (byte-identical behavior) and now **raises** on any
   cross-tech collision instead of overwriting. Universal datasets that mix
   tsmc6 must build sidecars via `scripts/uni_concat_npz.py` (concatenates
   per-tech sidecars), never by fingerprint scan.

2. **No load-bearing parameter is silently dropped.** 265–410 assignments per
   device are expression-valued (`'2.53e-08*6.55'`, `agauss(...)`, flag
   params like `age_*`, `alter_flag`, mismatch hooks `w1..w99`,
   `wku0*`/`wkvth0*` stress-corner knobs) and are skipped by the numeric-only
   `_ASSIGN_RE`. Cross-referencing all skipped names against the OSDI
   descriptor: **zero are BSIM-CMG parameters** — all are HSPICE-side
   corner/statistical/aging/LOD scaffolding that OSDI could not consume
   anyway.

3. **Mid-line `*` is multiplication, not a comment — current behavior is
   correct; do NOT "fix" it.** `_extract_model_params` does not strip
   mid-line `*` (unlike `parse_modelcard`); inside the PDK blocks every
   mid-line `*` sits inside a quoted expression (`lku00 = '4.431e-17*1.3'`),
   and 1,112 legitimate numeric parameters ride on such lines AFTER the
   quoted expression. A comment-stripping "unification" would delete them.
   Verified: zero numeric assignments originate from true comments inside
   model blocks. (`parse_modelcard`'s stripping is safe on its input — naive
   cards contain no expressions.)

4. **Bin-boundary selection is inclusive-both-ends; HSPICE is
   `lmin ≤ L < lmax`.** 28–40 of each device's PDK-derived (L, NFIN) sweep
   points sit exactly on shared bin boundaries and match >1 bin;
   first-in-file-order wins. This is self-consistent everywhere it matters —
   PyCMG and NGSPICE consume the SAME selected naive card, and gates pass at
   <0.1 % — but at exact boundary points the selected bin can differ from
   what HSPICE+full-PDK would pick. Accepted (changing selection would move
   every baseline); noted for anyone comparing against HSPICE at bin edges.

5. **TSMC sentinels (±999·10ⁿ) appear only in TSMC5** (25 per device) and are
   correctly dropped by mantissa arithmetic.

6. **~1,100–1,950 numeric params per naive card are unknown to the OSDI
   descriptor** (TMI hooks `tmi*`, statistical/LOD numerics). `apply_param`
   silently ignores unknown names — on the PyCMG side and identically inside
   NGSPICE's OSDI layer — so both consumers see the same effective parameter
   set. Accepted: harmless and symmetric; stripping them would shrink cards
   ~4× but would touch all cached cards of the 4 legacy techs for zero
   behavioral gain.

### Accepted simplifications (the "naive TT card" contract)

The pipeline reads exactly two `.model` blocks per device — `{base}.global` +
the L/NFIN-selected bin — and flattens them. Deliberately out of scope, for
all techs: PVT corners (`.lib` skew sections; nominal TT only), statistical /
Monte-Carlo / mismatch (`agauss` + `w*` hooks), aging/TMI `.lib` sections,
wrapper-subckt parasitics (PODE/diode/BJT/RC networks), self-heating (cards
themselves set `shmod=0`), IO/1.8 V voltage-domain devices, and instance
params (L/W/TFIN/NFIN/NF/MULTI supplied at instantiation; NFIN≥2 per the
known convergence constraint). These bound what "ground truth" means: the
nominal-TT core FinFET, which is what NGSPICE is fed too.
